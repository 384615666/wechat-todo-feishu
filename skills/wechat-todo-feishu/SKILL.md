### ② 本 skill 的用途与用法

- **触发**：说"更新待办 / 生成今天的待办 / 同步飞书 / 整理微信消息 / 跑一下待办"即可；
- **干四件事**：扫微信增量消息 → 写待办文件 → 双写飞书（多维表格台账 + 飞书任务）→ 归档新文件 → 汇报；
- **依赖 1（微信读取）**：wechat-cli（`~/.wechat-cli/wxcli.cmd`）与检索脚本 `search_all.py` **已由安装器随包装好**（后者位于 `skills/wechat-local/scripts/`）。首次运行先验一步：`wxcli sessions` 能返回会话列表即可用；若报密钥错误或出乱码，保持微信运行后跑 `~/.wechat-cli/wxcli.cmd init` 重建密钥（config.json 的 db_dir 会自动探测），结果告知用户；
- **依赖 2（飞书）**：通过**本机 `lark-cli`** 操作飞书（安装器已预检；未就绪时其他步骤照常做，飞书同步步骤跳过并在汇报中明确说明）。

### ③ 验证飞书 CLI（本机已连接 lark-cli 的话只做验证，不做任何注册）

飞书同步的**两个目标**：

- **飞书任务**（执行层）：每条待办 = 一个真正的飞书任务，手机端弹提醒、可勾选完成、能回读勾选状态；
- **多维表格「微信待办台账」**（台账层）：全部待办一行一条（含无截止占位），是**去重索引**与全量记录。

按顺序验证：

1. **登录态**：`lark-cli auth status --json --verify` 必须返回已登录且身份正确。若未登录：在 ZCode 环境走 `lark-cli` 官方 setup skill 完成连接；非 ZCode 环境按 lark-cli 自身文档登录。**不要拿别的身份顶替**；
2. **能力探查**：`lark-cli --help` 列出全部业务域，再分别 `lark-cli <域> --help`，确认两件事——
   - 多维表格（base/bitable 域）记录的**查、插、改**子命令可用；
   - **任务域**（task/todo）的查/建/改子命令是否存在。若该版本 lark-cli 没有任务域：台账单写照常，飞书任务提醒层跳过（每次汇报注明），或与用户约定改用日历域挂截止提醒；
3. **建台账**（一次性）：用 lark-cli 多维表格域新建「微信待办台账」，数据表含 7 个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| 任务 | 多行文本 | 任务标题（单日期，含上下文） |
| 截止日期 | 日期 | 无截止留空 |
| 状态 | 单选 | 待办 / 已完成 / 作废 / 占位待补日期 |
| 优先级 | 单选 | 高 / 中 / 低 |
| 来源 | 多行文本 | `群名 · 发送人 · 时间`；个人自建写"个人自建任务" |
| 任务ID | 多行文本 | 飞书任务的 task guid，回读对账用 |
| 原文摘录 | 多行文本 | 通知原文（或关键句），核对用 |

   若用 CLI 建字段不便，直接在飞书客户端手动建表也可。**无论哪种建法，都把表格 URL（含 app_token）和 table_id 写进工作区 README.md 的"飞书台账"区**，以后每次同步从这里读。

**验证标准**：用 lark-cli 向台账插一条测试记录并读回可见；任务域存在的话建一条标题带"测试"的任务、到飞书「任务」里能看到；验证通过后**删除测试数据**。

验证通过后回到对话，告诉 agent"飞书 CLI 已验证"。

## lark-cli 使用规约（每次飞书操作都遵守）

1. **先验身份**：会话内第一次调 lark-cli 前先 `lark-cli auth status --json --verify`；默认显式 `--as user`（用户身份），需要机器人身份时必须由用户明确指定；
2. **不猜命令**：确切子命令与参数一律用 `lark-cli --help` / `lark-cli <域> --help` 实时确认，不凭记忆写命令；
3. **结构化输出**：优先 JSON 输出，只保留所需字段；**成功判定 = 退出码 0 且 `ok == true`**，不使用顶层 `code == 0`；失败 JSON 通常在 stderr；
4. **写操作门禁**：批量建/改任务与台账行前，先把"待建 N 条 + 待改 M 条"的摘要展示给用户确认一次，再批量执行；退出码 10 / `confirmation_required` 是高风险确认门禁，取得用户明确确认后才按帮助追加确认参数，不自动绕过；
5. **不泄露凭据**：不输出 token、Cookie、配置文件内容；权限不足按当前身份与所缺 scope 如实上报，不换账号硬试。

## 铁律（每条都出过事故，违反即 bug）

1. **绝对日期，永不写"今天/明天"**：文件标题、章节标题只允许 `2026-10-05` 这种绝对日期；相对日期一觉醒来就是错的。
2. **总表倒叙**：`待办总表.md` 按日期倒序——最新的截止在最上面，旧的自然下沉；每天只在顶部插新区块。
3. **扫全部活跃会话，不许用固定群名单偷懒**：任务经常发在新拉的群里。每次运行必须先 `wxcli sessions` 列全量，凡断点之后有新消息的逐个看；新群/新联系人默认"可能有任务"。
4. **飞书单任务单日期**：一条飞书任务从标题到 due 到正文自述只允许一个日期；跨多日期的事项拆成多条各挂各日。正文写来源不带日期，历史进展不带日期；末尾【原始信息】原文照抄区天然带日期，不算违反。
5. **用户范围限定**：每个用户的适用范围不同（校区、年级、职务、身份）。第一次运行时向用户确认其范围限定词并写进 README（如"我是 X 校区学生""我只做 X 职务的活"）；通知原文限定别人做的事，一律不派给用户、记入作废区并注明原因；建任务时不许丢原文的范围限定词，存疑先看原文再建。
6. **任务正文与台账必附来源**：每条飞书任务的描述末尾追加 `【原始信息】（来源群 · 发送人 · 时间）` + 通知原文逐字照抄（含随附文件名）；同一事项拆多条的每条都要附；台账"来源"列同步写；个人自建任务写 `【原始信息】个人自建任务，无微信原文。`。
7. **凡有日期/时间的事项一律建飞书任务，全部事项一律入台账**：活动日、截止日、报名窗口、可选活动、收到免回复的小事——不管多小都要建任务并挂日期；没具体日期的也建任务（不挂截止）并在台账标"占位待补日期"；范围型事项建一条挂起始日或截止日。**台账是全量记录（含无截止事项），飞书任务放要提醒的事项。**
8. **去重三查**：新建任何任务前，必须同时查**台账全部记录 + 飞书未完成任务 + 飞书已完成任务**——台账已有的不重复插行；已打勾的（飞书任务已完成）一律视为已完成，既不重建也不再提醒，台账状态同步改"已完成"；历史完成也进总表"已完成"区。
9. **优先级排序**（可被用户在 README 覆盖）：默认 **用户本人组织/职务的事（学生会、班委、部门） > 老师/班主任/上级发的 > 其他按截止紧急度**；汇报、总表与台账"优先级"列都按此。
10. **新文件必归档**：断点后收到的每个文件（docx/xlsx/pdf/zip/图片等）都要找到本地缓存、打开确认内容，按用户在 README 约定的文件夹分类归档；重复副本比对后处理；归档记录写进纪要和汇报。

## 工作流（按序执行，不可跳步）

### Step 0 · 定日期和断点
- `date +%F` 取今天真实日期，不许沿用文件里的日期。
- 读工作区 `README.md` 的"数据截至"时间戳 = 上次断点；同时读"飞书台账"区拿表格 URL（app_token）与 table_id。
- 读 `待办总表.md` + `今日待办.md`，把所有 `- [ ]` 未完成项抄到临时清单——这是衔接校验的基准。

### Step 1 · 列全量会话，找断点之后动过的
```bash
export PYTHONIOENCODING=utf-8
~/.wechat-cli/wxcli.cmd sessions --limit 80
```
凡 `time` 晚于断点的会话全部进入扫描列表；对比 README"必盯清单"，没记录过的新群/新联系人优先扫并加进清单。公众号/资讯号跳过。

### Step 2 · 导出增量
```bash
~/.wechat-cli/wxcli.cmd history "<会话名>" --start-time "<断点日期 00:00 或上一断点>" --format text --limit 300
```
只看：班级/工作/通知群、老师上级、班委、私聊；**起点比断点早几小时**，防止会话列表分页漏掉边缘消息。要拿链接/文件详情时用 `--format json`。

### Step 3 · 关键词补盲
```bash
python <wechat-local>/scripts/search_all.py 截止 --context 3 --limit 40
```
换词多跑几轮：截止 / 交 / 报名 / 接龙 / 收到请回复 / @所有人 / 前；输出用 `grep "YYYY-MM-DD"` 过滤到断点后。**以 search_all.py 为准**（wxcli search 对压缩消息失明）。

### Step 4 · 判定与分类
每条新消息归入：**新待办（带截止）/ 已完成 / 作废（澄清误传、范围外）/ 纯通知 / 纯闲聊**。同一事项多次改期取最新；"发错了/不要看"标删除线进作废区；范围限定词先对照 README 里用户的范围再判定；**别人私聊交代的事优先级高于群通知**。

#### 私聊来信必须走语义分流，禁止机械判定

> ⚠️ **铁律：不许用「最后一条是谁发的」判断对方是否在等我。** 「好的，谢谢」「好滴」「收到」都是收尾语，机械规则会把人家的道谢算成"待回"——2026-11-03 实测把 7 个真正待办误报成 13 个。

```bash
python <skill目录>/scripts/triage_incoming.py --hours 24 --json /tmp/triage.json
```

脚本做的事：取每位私聊联系人最近 8 条**双向**正文 → 交给模型做语义判定 → 输出四类：
`待我动作` / `已收尾` / `等对方` / `无实质`，并给出依据与具体动作。

| 类别 | 判据 | 后续 |
|---|---|---|
| **待我动作** | 对方在等答复/交付、提新要求；我方承诺（今天修/中午/过两周/稍后）未兑现；对方只发文件/链接未回应；对方给出指令需我方执行 | 进 Step 6/7 待办，Step 8 建飞书任务 |
| **已收尾** | 对方末句是收尾语且诉求已在我方上一条闭环 | 不进待办，最多记入纪要 |
| **等对方** | 最后一条是我方发的（发链接/给方案/提问），无未兑现承诺 | 不进待办，标"等对方" |
| **无实质** | 纯寒暄、新加好友招呼、系统消息 | 忽略 |

配置：默认复用本机 DSH 的 newapi 端点（`~/.dsh/settings.yaml.imported` + `~/.dsh/.credentials.yaml` 的 `NEWAPI_API_KEY`，模型 `deepseek-flash`）；也可用环境变量 `TRIAGE_BASE_URL` / `TRIAGE_API_KEY` / `TRIAGE_MODEL` 换端点。
隐私：微信数据仍在本机解密，**只有对话正文 + 「联系人NN」匿名标签**会发给模型端点，真实姓名不进 prompt；不同意出网就加 `--no-llm`（会误判，仅排障用）。
脚本对推理模型的空返回有兜底：重试 → 从 `reasoning_content` 捞 JSON → 二分批次重喂。

### Step 5 · 写 `日期纪要/YYYY-MM-DD.md`
每天一个文件，模板照抄前一天：当日要点、时间线表格、勾选清单、前瞻。

### Step 6 · 重写 `今日待办.md`
标题 `# 📌 今日待办 · <绝对日期>（周X）`。结构：⚡ 今天必须做（硬截止）→ 🟡 今天顺手处理 → 📅 接下来（按日期排序，只放未完成）→ ✅ 今天已完成 → ⚠️ 已作废。旧文件所有未完成项必须结转。

### Step 7 · 重写 `待办总表.md`（倒叙）
章节顺序（新的在上）：🔺 新增/更新 → 🔴 已过期/待确认 → 🟠 未来 7 天 → 🟡 远期截止 → 📖 长线 → 🔵 条件触发 → 📢 提醒类 → ✅ 已完成（倒序）→ ❌ 作废。每条写绝对截止日期。
**衔接校验（必做）**：Step 0 的旧未完成清单逐条对照新总表——每条要么还在、要么进已完成、要么进作废，三者之外不允许凭空消失，丢项立即补回。

### Step 8 · 飞书同步（lark-cli；台账 + 任务双写，去重后提交）
先过一遍上方「lark-cli 使用规约」（验身份、--help 确认子命令、--as user）。然后：
1. **查台账**：用多维表格域的记录查询子命令拉全部记录，载入去重索引（任务标题 + 截止 + 状态）。
2. **查任务**：用任务域查未完成任务；再查断点以来已完成的任务——**用户在飞书里勾掉的，一律视为完成**，台账状态改"已完成"，不翻用户的案。（该版本 lark-cli 无任务域时：此步跳过，台账单写，汇报注明。）
3. **状态对账**：有明确证据闭环的（原文撤回、澄清、完成证据）→ 任务域标完成 + 台账改状态，两边都不许漏；两边记录冲突时以飞书任务状态为准（它是提醒层），台账补记。
4. **建新任务**（排除三查已存在的）：
   - 有具体日期：任务域创建（标题单日期；描述放详情 + 末尾【原始信息】原文；截止挂当日，具体到小时则挂时间）；无截止：也建任务但不挂截止时间，台账标"占位待补日期"。
   - 所有新增（含无截止占位）同时写台账行，"任务ID"列回填 task guid，"来源"列写 `群名 · 发送人 · 时间`。
   - 已存在的台账行如有更新（改期、补充信息）：更新对应行，不重复插行。
5. 按铁律 9 定优先级（台账"优先级"列 + 文件排序都体现）；逐条记录 taskId / record_id，汇报里列出"新建 N、勾掉 M、排除重复 K"。

### Step 9 · 文件归档
按铁律 10 找文件、开文件确认、分类移动/复制、记录。

### Step 10 · 更新 README 并汇报
- "数据截至"刷成本次时间；必盯清单加新群；"接下来最关键"改成当前视角。
- 按下面格式向用户汇报。

## 输出汇报格式

1. 本次断点→新断点的时间范围、扫了几个会话、新发现的群；
2. 新增待办（带绝对截止日期，按铁律 9 的优先级排序，每条写详细、有文件的点进去看了什么）；
3. 状态变化（完成/作废/改期/待确认）；
4. 飞书操作明细：新建任务 N 条（标题+日期）、台账插行 N 条、勾掉 M 条、排除重复 K 条；若 lark-cli 未就绪或无任务域，此处明确说明"本次仅写本地文件/仅台账，飞书任务未同步"；
5. 文件归档明细（文件 → 去向文件夹）；
6. 衔接校验结果：旧 N 条未完成 → 现在都在哪；
7. 最近 3 天的硬截止 Top3。

## 工具坑速查

| 坑 | 解法 |
|---|---|
| `search_all.py` 报解密缓存缺失 | 先跑 `wxcli history 任意群 --limit 3`（只跑 sessions 不够） |
| `search_all.py` 报 `zstandard has no attribute ZstdDecompressor` | 临时目录坏包缺 `__init__.py`：把 `~/.wechat-cli/deps/zstandard/*` 复制到 `%LOCALAPPDATA%\Temp\wechat-cli-plus-pydeps\zstandard\` |
| `--context` 裸 flag 报错 | 必须带值：`--context 3` |
| bash 下中文输出乱码 | `export PYTHONIOENCODING=utf-8` |
| bash 里中文变量名赋值失败 | 用纯英文变量名或直接写完整路径 |
| wxcli search 搜不到通知 | 压缩消息盲区，用 search_all.py |
| lark-cli 报未登录/token 过期 | 重新走 lark-cli 登录流程（ZCode 里用官方 setup skill），不要拿别的 profile 硬顶 |
| lark-cli 报权限/scope 不足 | 按当前身份与所缺 scope 上报用户，在 lark-cli 侧补授权；不要换身份绕过 |
| lark-cli 写操作退出码 10（confirmation_required） | 这是高风险确认门禁：向用户展示变更摘要，拿到明确确认后按 --help 追加确认参数，不自动绕过 |
| 该版本 lark-cli 没有任务域 | 台账单写 + 汇报注明；或与用户约定用日历域挂截止提醒 |
| 台账日期字段写不进 | 飞书日期字段多要毫秒时间戳或其规定的格式，按字段说明转换，别传字符串日期 |
| 文件被并发改动（Edit 报 modified） | 重 Read 再改；多会话共用工作区 |
